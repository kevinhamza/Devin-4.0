# Devin AGI - Ethical Hacking & Penetration Testing Guidelines

## 1. Guiding Principle: Do No Harm

All security testing activities conducted by or through the Devin AGI must be guided by the primary principle of "Do No Harm." The goal is to identify vulnerabilities for the purpose of improving security, not to cause damage, disruption, or data loss.

---

## 2. The Principle of Explicit Authorization

**Authorization is mandatory and non-negotiable.**

- **Written Consent:** Before initiating any form of security testing (including reconnaissance, scanning, or exploitation), the operator must obtain explicit, written authorization from the owner of the target system(s).
- **"Get Out of Jail Free" Card:** This authorization, often referred to as a "Penetration Testing Authorization Agreement," is the controlling document for the engagement. The `cyber_law/warrant_generator.py` module should be used to create this document.
- **No Unsolicited Testing:** Devin must never be used to probe, scan, or attack any system for which authorization has not been granted.

---

## 3. The Principle of Scope Adherence

**Stay within the agreed-upon boundaries.**

- **Defined Targets:** The authorization document must clearly define the scope of the test, including specific IP addresses, domains, applications, and networks.
- **Off-Limits Systems:** Any system not explicitly listed in the scope is considered off-limits. Devin must be configured to avoid any interaction with out-of-scope systems.
- **Time Boxing:** All testing activities must be confined to the start and end dates specified in the authorization agreement.

---

## 4. The Principle of Confidentiality

**All findings are considered highly confidential.**

- **Data Handling:** Any data discovered or exfiltrated during a test (e.g., user credentials, database contents, configuration files) must be handled with the utmost care.
- **Secure Storage:** Sensitive findings must be stored in an encrypted format.
- **Disclosure:** Findings must only be disclosed to the authorized parties named in the authorization agreement. Public disclosure is strictly forbidden unless part of a coordinated and responsible disclosure process agreed upon by the client.

---

## 5. The Principle of Responsible Disclosure

**Report findings in a clear, actionable, and responsible manner.**

- **Timeliness:** Vulnerabilities should be reported to the client as soon as they are validated.
- **Clarity:** Reports generated by Devin should be clear, concise, and provide enough detail for the client's technical teams to understand, reproduce, and remediate the vulnerability.
- **Remediation Focus:** The primary goal of reporting is to empower the client to fix security weaknesses. Reports should, where possible, offer constructive recommendations for mitigation, leveraging the `threat_intel/intel_feeds/mitre_attack.py` module to map findings to known mitigation strategies.
